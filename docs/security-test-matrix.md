# Relay Security Test Matrix: Section 22.3 Negative Tests

This document maps all 35 negative security requirements specified in Section 22.3 of `docs/SPEC.md` to automated tests in the test suite. Every item has at least one dedicated test file and test name validating the security invariant.

> [!WARNING]
> **Security Limitation Notice (Section 22.3 & 2A.4 Item 6)**
> A finite automated test suite does not mathematically guarantee zero data leakage. While the negative test matrix below rigorously verifies access control enforcement, multi-tenant boundaries, epoch invalidation, schema immutability triggers, log hygiene, and adversarial input rejection across all defined execution paths, software alone cannot guarantee that human-authored free-text summaries or review notes contain no restricted knowledge. Human review and explicit reviewer attestation (`confirmReviewedForRecipient`) remain an indispensable layer of defense in depth.

## Verification Summary

All 35 negative security test cases have been implemented across unit, integration, and end-to-end security test suites. Running the verification suite executes every test to green status against a running local Supabase instance:

```bash
npm run test:security
```
